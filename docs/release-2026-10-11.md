# 11 October 2026 release

The owner requested the accepted staged changes on master in one commit and a live
deployment. The concurrently edited, unstaged fleet pace/fuel task is excluded;
its files and the shared-file edits remain in the owner's working directory.
This release includes admin operations and moderation, placement telemetry,
telescope query batching, worker scheduling, fullscreen, special hull explanations,
fractional battle-report damage, premium visuals/audio and local world preparation.

The top menu planet remains the original static image; the galaxy background
remains the original implementation. Production uses the Git-tracked Astera
assets: research illustrations, short sound effects, explosion atlas, wreck model
and lighting/material changes. The optional `astera-refs` archive and prepared
reference ship/rock files remain development-only and are absent from production.

Migration 0148 adds account-scoped chat mutes and a private admin audit trail.
Migration 0149 adds owner/departure indexes for mining and pirate activity reads.
Both are additive. The release preserves the placement pool default of two and
does not change rules, season deadlines, capacities, asteroid calendars or player
inventory. Admin capital provisioning is the explicitly implemented operator-only
boot/join reconciliation; ordinary capitals retain their progression and placement.

Read-only production inspection confirmed that EU-1, EU-2 and WAIT-1 are already
live at ruleset 16, matching `MULTI_WORLD.rulesetVersion`. This release applies to
those active seasons without a reset or an in-place ruleset upgrade. Future
season creation continues to read the current rules package default.

Release review found an old-client compatibility gap in hidden admin clan
messages: the previously published client requires a string `planetId`. Hidden
authors now return an empty ID, retaining that parser contract without disclosing
an admin world. The new client does not offer a location action for empty IDs.
The existing admin HTTP regression checks this legacy boundary. Local bring-up
fixtures now match `local-bootstrap`, its environment rejection and the LAN Vite
arguments.

Local qualification runs sequentially at priority 19 on one CPU, with one test
worker and no file parallelism. Concurrent pace/fuel edits appeared during the
first full run, so final qualification uses an immutable export of the staged
Git tree, not the changing working files. The export has no Git branch or worktree.
A resource-limited VPS container and dedicated PostgreSQL container verified all
four workspace typechecks without using the live database. The final ordinary
quality gate runs against the pushed commit in repository CI, on a separate runner
and test database. Long economy/season simulations and snowball audits are excluded.
The preceding visual review and its remaining device/coverage limits
are recorded in [premium-code-review-20261011.md](premium-code-review-20261011.md);
the deployment request adds ordinary release qualification, rather than claiming
physical phone performance measurements or completion of every proposed new test.

The first CI pass found two StarField regressions: an inline shade bypassed v2
palette tokens, and the deterministic-sky test compared React's instance-specific
SVG IDs. The shade now uses a token at the same RGB value. The test still compares
all sky markup while normalizing those IDs, and also checks that each sky owns a
distinct gradient referenced by its halos. Both targeted suites pass (32 tests).

The production runbook is [deployment.md](deployment.md). Before migration, retain
the old image, webroot and Nginx route; restore a consistent production dump into
a disposable database and compare table counts. Build both artifacts from the
single pushed SHA, migrate the restored copy and require the retained old image
to run against its new schema. Old/new image probes also drain copied scheduled
events, with bots disabled, private test tokens and local rate-limit buckets;
they never process the production database or share its request counters.
Only then apply production migrations and roll
API1, API2, API3 and the singleton worker in sequence. Publish the complete webroot
by rename after internal acceptance, retaining old immutable assets for open tabs.

Acceptance requires all four processes to report the same image and full SHA,
150 applied migrations, zero failed events or overdue missions, unchanged live-season rows,
the public release marker and matching per-request CSP nonce, and a clean browser
smoke. Production season operations, local grants/spawns and local-bootstrap are
not deployment steps. The latter rejects production before querying world data.

Private backup, restore and deployment evidence lives under
`~/astera-deploy-evidence/` on the VPS, outside Git. Local qualification logs live
under `.dev/release-20261011/`; external browser evidence belongs in `out/`.
