2. Yukarıda geri yüklenen ayrı prova DB'sinde 0185'i **gerçek aday image ve mevcut migration runner** ile uygula. Migration prefix/hash, lock/statement bütçesi, journal 185→186, eski hesap/dünya/filo/event korunması ve beklenmedik fault backfill'i denetlenir. Yalnız tablo SQL'inin çalışması yeterli değildir. Prova servisleri production DB'ye bağlanmaz; ayrı JWT ve kapalı mail/billing/bot servisleri kullanır. Eski ve yeni image ile web okuma/yazma uyumluluğunu, native oturum/CORS/SSE/iptali kanıtla.
3. Taze canlı SHA/env/health/aktif iş envanteri ve ana runbook kapılarıyla olağan compatible roll seç. Gereksiz bakım/wipe/sezon aktivasyonu yok. Sınırlandırılmış migration yalnız bir kez uygulanır; üç API ve singleton worker aynı yeni kodu anlayana kadar native auth kapalı kalır. Beklenmeyen kilit/uyumsuzlukta işlemi durdur; olağan roll ötesinde kesinti kendiliğinden uygulanmaz.
4. Bütün replikalar uyumluyken Android `https://localhost`, ileride iOS `capacitor://localhost` origin'leriyle native auth'u aç. HTTP localhost yalnız yerel geliştirmedir, production NODE_ENV'de reddedilir. Ayrı native JWT amacı eski replikada da reddedilir; karma sürümde native özelliği açarak aralıklı 401 üretme. Web cookie/JWT anahtarları ve mevcut hesaplar korunur.
5. `https://asteraonline.space` üzerinde TLS/nginx/Cloudflare üzerinden OPTIONS/401/CORS/Vary/clock/placement ve **gerçek akan** SSE kabulünü tamamla. API olarak yönlendiren `api.` domain'ini kullanma: dar native HTTP redirect reddeder. Gerçek oyuncular üzerinde sahte kayıt/filo/satın alma testi yapma; yazan regresyonlar prova DB'sindedir. Kendi hesabına cihazdan giriş gerektiğinde sahibin uygulamada giriş yapması yeterli; parola alınmaz/loglanmaz.
6. Aynı SHA'dan `VITE_ASTERA_API_URL=https://asteraonline.space pnpm android:bundle native-production` üret. Bu hâlâ **bundled debug**, storeReady=false ve Gradle release kapalıdır. USB reverse'süz Wi-Fi/mobil veri, kill/relaunch, ağ geçişi, native medya ve geri/lifecycle testleri gerekir; AAB/signing kabulü değildir.

Mevcut stage alternatif izole ortam olarak korunur; dokuz migration gerideki stage'i sırf mobil URL testi için wipe etmek veya production verisi/JWT'siyle bağlamak gerekmez. Stage seçilirse kendi env/backup/prefix ve bütün pending migration'ları ayrıca prova edilir, `native-staging` hedefi kullanılır. Kullanıcının son canlı API hedefi, production snapshot'ının ayrı kopyasıyla yapılan yayın provasını atlatmaz.
